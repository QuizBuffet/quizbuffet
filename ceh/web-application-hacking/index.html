Sample Questions

Which web server component handles incoming HTTP requests, routes them to the appropriate application logic, and returns the resulting HTTP responses to clients?

Answer: Web server software (Apache, nginx, IIS) — the HTTP server process that receives connections, parses requests, and delivers responses

Web server software (Apache HTTP Server, nginx, Microsoft IIS, Caddy) is the core component that: listens on TCP ports 80 (HTTP) and 443 (HTTPS), accepts client TCP connections, parses incoming HTTP request headers and body, routes requests to appropriate handlers (static files, CGI scripts, reverse proxy to application servers), and constructs and returns HTTP responses. In a multi-tier architecture, the web server may also function as a reverse proxy forwarding dynamic requests to application servers (Tomcat, Node.js, Gunicorn) while serving static content directly.

Which security control specifically limits what a web server process can access on the host operating system — preventing a compromised web server from reading sensitive system files, writing to system directories, or accessing other processes' memory?

Answer: Running the web server process with minimal OS privileges (non-root user account) combined with OS-level access controls (AppArmor, SELinux, chroot jail) — limiting the blast radius if the web server process is compromised

OS-level privilege minimization is the principle of least privilege applied to web server processes: (1) Non-root user — Apache runs as 'www-data' (Debian/Ubuntu) or 'apache' (RHEL/CentOS) with no sudo access and no home directory write access. A compromised web server running as www-data cannot read /etc/shadow, install system services, or access other users' files. (2) AppArmor/SELinux profiles — mandatory access control policies that further restrict exactly which files, directories, and system calls the web server process can use, regardless of Unix permissions. (3) chroot jail — changes the apparent root directory for the web server process, confining it to a limited subtree. Together these limit post-compromise damage.

A web server administrator discovers that the organization's Apache installation has 47 Apache modules loaded, including many that are enabled by default but not used by any application. Which security principle does disabling unused modules implement, and which specific security risk does it reduce?

Answer: Principle of Least Functionality — reducing the attack surface by disabling modules that are not required eliminates code paths with potential vulnerabilities (mod_status, mod_info, mod_userdir, mod_autoindex) that could be exploited even if the core application is secure

The Principle of Least Functionality (also called attack surface reduction) specifies that systems should only have the capabilities, services, and features required for their intended function. Unnecessary Apache modules add code with potential vulnerabilities that are exploitable even when the core application is completely secure: mod_status (exposes real-time server status at /server-status including request details and client IPs), mod_info (exposes configuration at /server-info), mod_userdir (enables ~/username URL mapping that could expose sensitive files), mod_autoindex (directory listing), mod_cgi/mod_cgid (CGI execution — a significant attack surface if not needed). Each disabled module eliminates a class of vulnerabilities from the attack surface entirely.
