Sample Questions

How does a MAC flooding attack work against a network switch, and what is the result when the CAM table is exhausted?

Answer: MAC flooding sends frames with thousands of unique fake source MAC addresses, exhausting the switch's Content Addressable Memory (CAM) table — when full, many switches fail open and flood all frames out all ports (behaving like a hub), enabling passive sniffing

A MAC flooding attack (using tools like macof from the dsniff suite) sends frames with randomly generated fake source MAC addresses at high volume. The switch learns each new source MAC, adding it to the CAM table. When the CAM table reaches capacity, the switch can no longer learn new legitimate MAC-to-port mappings. Many switches (particularly older models) respond by 'failing open' — flooding frames for unknown destination MACs out all ports, converting from unicast switching to hub-like broadcasting. An attacker connected to any switch port can now capture all traffic in the VLAN using promiscuous mode.

A network engineer wants to prevent MAC flooding attacks on access layer switches. Which Cisco switch security feature directly limits the number of MAC addresses learned on each port?

Answer: Port Security — configures a maximum number of MAC addresses per port and defines violation actions (protect, restrict, shutdown) when the limit is exceeded

Cisco Port Security is specifically designed to prevent MAC flooding by limiting MAC address learning per port: (1) 'switchport port-security maximum 1' limits the port to 1 MAC address (for end-user access ports). (2) 'switchport port-security violation shutdown' disables the port if the limit is exceeded (most secure). (3) Alternative violations: 'restrict' (drops violating frames, sends SNMP trap) and 'protect' (silently drops violating frames). (4) 'switchport port-security mac-address sticky' dynamically learns and persists the first MAC seen. When macof generates thousands of fake MACs on a port with port-security maximum 1, the first fake MAC triggers a violation and the port shuts down — protecting other ports from the overflow attack.

ARP (Address Resolution Protocol) has a fundamental design weakness that enables ARP poisoning attacks. What is this weakness?

Answer: ARP has no authentication mechanism — any host can send an ARP reply claiming any IP-to-MAC mapping, and receiving hosts accept and cache these replies without verifying their authenticity

ARP (RFC 826, 1982) was designed for trusted network environments with no authentication requirement. ARP has no mechanism to verify that the sender of an ARP reply is the legitimate owner of the claimed IP address. When a host receives an ARP reply — whether solicited or unsolicited (gratuitous) — it simply updates its ARP cache with the MAC-IP mapping in the reply without any validation. This allows any host on the local segment to: (1) Send an unsolicited ARP reply claiming 'IP 192.168.1.1 is at MAC aa:bb:cc:dd:ee:ff' (the attacker's MAC). (2) All receiving hosts update their ARP caches. (3) Traffic for 192.168.1.1 is sent to the attacker's MAC. The design assumption was that all hosts on the local network were trusted — a false assumption in modern environments.
