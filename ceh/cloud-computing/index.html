8.0 Cloud Computing — CEH Practice Quiz

28 exam-style questions covering 4% of the CEH exam. Instant feedback on every answer, progress tracking, no signup required.

This domain is part of the Certified Ethical Hacker (CEH) practice test. Each question is tagged by exam objective and difficulty so you can drill exactly the areas you need.

Sample Questions

Which three terms correctly identify the primary cloud computing service models as defined by NIST SP 800-145?

Answer: Infrastructure as a Service (IaaS), Platform as a Service (PaaS), and Software as a Service (SaaS)

NIST SP 800-145 defines three cloud service models: IaaS (provider manages physical infrastructure and virtualization; customer manages OS, middleware, and applications), PaaS (provider manages OS and runtime; customer manages applications and data), and SaaS (provider manages the entire stack; customer manages only user-level configuration and data).

What is the fundamental architectural difference between a container and a traditional virtual machine?

Answer: Containers share the host OS kernel and isolate at the process level; VMs run separate guest OS instances on a hypervisor

Containers (e.g., Docker) share the host operating system's kernel and use Linux namespaces and cgroups to isolate processes, filesystems, and network stacks at the OS level. Virtual machines run a complete separate guest OS on top of a hypervisor (Type-1 or Type-2), with no kernel sharing. This makes containers lighter and faster to start, but means a kernel vulnerability can potentially affect all containers on the host.

Which characteristic of serverless functions MOST significantly expands the application attack surface compared to a traditional monolithic web server deployment?

Answer: Multiple event trigger sources (HTTP, queues, storage events, streams) introduce injection and input validation risks at every integration point

Serverless functions can be triggered by a wide variety of event sources: API Gateway HTTP requests, SQS queues, S3 object events, DynamoDB streams, SNS notifications, scheduled events, and more. Each trigger type represents a separate input channel that must be validated and sanitized. Attackers can inject malicious payloads through any of these sources — a single function might process input from five different untrusted sources, each requiring its own validation logic.
